# `frame:tx` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An experimental `frame` module whose `frame:tx` block becomes one EIP-8141 frame transaction, sent by the CLI to the alt-mempool devnet with a confirmed local key.

**Architecture:** `frame:tx` interprets its block, turns the actions it gets back into an SDK `FrameAction` (frames fully laid out, shape checked), and returns it. Core refuses that action by default; the CLI supplies a `frame` handler built on `@evmcrispr/viem-frames`. The CLI's local key is wrapped so that every signature it makes (frame, provisional, ordinary) is shown and confirmed first.

**Tech Stack:** TypeScript, bun test, viem 2.56.8, `@evmcrispr/viem-frames` (workspace, private), `@forshtat/hegota-support` 0.0.1.

**Spec:** `docs/superpowers/specs/2026-11-06-frame-tx-design.md`

## Global Constraints

- Branch `viem-frames`. Short single-line commit messages, no attribution lines. Before pushing, regroup commits by theme (AGENTS.md "Commits").
- `@evmcrispr/core` and `@evmcrispr/sdk` must not depend on `@evmcrispr/viem-frames`. Only `packages/cli` does.
- Std learns nothing about frames: no change to `modules/std`.
- The key comes only from `EVMCRISPR_PRIVATE_KEY`; it is never printed, never in an error, never passed to the EVML environment. It is exclusive with `--wallet-rpc`/`--account`.
- No signature without confirmation: in a TTY a y/N prompt; without a TTY only with `--yes`. This covers the provisional transaction of `--size-by-simulation`.
- Only chain 1337 (the alt-mempool devnet) sends frame transactions; any other chain is refused with its name (`chainLabel`).
- Module `frame` is `experimental: true`. Out of scope: terminal sending, `--expires`, `deploy` frames, POST_TX, keyed nonces, P256, `sim:fork`.
- After admission the CLI waits 120 s for the receipt; if not mined, the run stops with the sidecar status and the explorer link `https://explorer.altmempool.wtf`.
- User-facing messages follow the SDK message helpers (`chainLabel`, no raw wei where a formatter exists).
- The pre-commit hook runs a repo-wide type-check: a task that changes a shared type fixes every consumer in the same commit.

## Review Focus

1. **A provisional signature sent without confirmation.** `--size-by-simulation` must show and confirm the provisional transaction (labelled provisional) before viem-frames signs it. Test in Task 5 (`confirms the provisional transaction before it is signed`).
2. **A `default`/`verify` action leaking out of `frame:tx`.** Imported unprefixed, `default ( exec … )` outside a `frame:tx` must throw, not run as an ordinary call from the sender. Test in Task 4 (`default outside frame:tx is refused`).
3. **A frame from another chain or sender.** `switch` inside the block, or an `exec` with a `from`, must be refused, not silently re-attributed. Test in Task 3 (`refuses a call from another sender or chain`).
4. **The key in output.** An error thrown with the key loaded (bad RPC, refused confirmation) must not contain it. Test in Task 5 (`never prints the key`).
5. **An unmined transaction followed by another from the same sender.** The run must stop after the 120 s wait instead of sending the next action. Test in Task 6 (`stops the run when the transaction is not mined`).

### Task 3: Laying out and checking the frames

**Files:**
- Create: `modules/frame/src/marks.ts`, `modules/frame/src/layout.ts`
- Test: `modules/frame/test/unit/layout.test.ts`

**Interfaces:**
- Produces (`marks.ts`): `markFrame(action: TransactionAction, mark: FrameMark): void`, `frameMarkOf(action: TransactionAction): FrameMark | undefined`, where `type FrameMark = { mode: "default" } | { mode: "verify"; approve: "execution" | "payment" | "both" }`. Backed by a module-private `WeakMap`.
- Produces (`layout.ts`):
  ```ts
  export interface LayoutInput {
    actions: Action[];          // what the block returned
    sender: Address;
    chainId: number;
    paymaster?: Address;
    paymasterData?: Hex;
    stateGas?: bigint;
  }
  export function layoutFrames(input: LayoutInput): FrameSpec[]; // throws ErrorException
  export const SELF_VERIFY_GAS = 30_000n;
  export const PAYMASTER_VERIFY_GAS = 50_000n;
  export const MAX_FRAMES = 64;
  ```
- Rules (from the spec, all in `layoutFrames`): a `TransactionAction` is one frame (mode from its mark, else `sender`; `target` null when it equals `sender`); a `BatchedAction` is its actions with `atomic: true` on all but the last; any other action type, a `readOnly` action, an action whose `from` differs from `sender` or whose `chainId` (when set) differs from `chainId` is refused. With no verify frame and no paymaster, prepend `self_verify` (`verify`, `both`, target null, gas `SELF_VERIFY_GAS`). With `paymaster`, prepend `only_verify` (`execution`, null, `SELF_VERIFY_GAS`) and `pay` (`payment`, paymaster, `paymasterData ?? "0x"`, `PAYMASTER_VERIFY_GAS`); a paymaster together with a written verify is refused. Then the prefix must be `[pv? self_verify]` or `[pv? only_verify, pv? pay]`, where `pv` is a `default` frame whose target equals the next verify's target; `execution`/`both` only target the sender; no verify after the prefix or inside an atomic group; at most `MAX_FRAMES`. `stateGas` is set on every frame after the prefix.

- [ ] **Step 1: Write the failing tests**, one per row, with fabricated actions (`{ to, data, value }` objects and `markFrame`):
  - `a call is a sender frame after a generated self_verify`: one action → `[{mode:"verify",approve:"both",target:null,gas:30_000n,…}, {mode:"sender",target:TO,…}]`.
  - `a batch is atomic but for its last frame`: a `BatchedAction` of three → `atomic` `[true,true,undefined|false]`.
  - `--paymaster prepends only_verify and pay`: `paymaster: P` → first two specs `execution`/null/30k and `payment`/P/50k.
  - `a default frame right before a verify with its target is its pre_verify`: written `[verify(sender, execution), default(P), verify(P, payment), call]` is accepted as written.
  - `a default frame elsewhere in the prefix is refused`: `[default(Q), verify(sender, both), call]` throws `/pre_verify/`.
  - `execution approval must target the sender`: `verify(P, execution)` throws.
  - `refuses a paymaster together with a written verify`.
  - `refuses a verify inside an atomic group` and `refuses a verify after a sender frame`.
  - `refuses a call from another sender or chain` (Review Focus 3).
  - `refuses more than 64 frames`.
  - `state gas goes on every body frame and no validation frame`.
- [ ] **Step 2: Run** `cd modules/frame && bun test test/unit/layout.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** `marks.ts` and `layoutFrames`. Error messages name the frame by its position (1-based) and say what to write instead.
